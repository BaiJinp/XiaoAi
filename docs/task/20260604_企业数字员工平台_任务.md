## 2. 需求确认快照

### 2.1 产品定位

当前阶段目标调整为：先做出一个真正好用的项目助理 Agent，让它能处理真实项目工作、展示执行过程、使用项目知识、处理必要审批并交付可复用结果。企业数字员工平台仍是长期方向，但平台化能力先后延，只作为支撑项目助理 Agent 的最小护栏和架构预留。

### 2.2 已确认核心原则

- 当前阶段是 Project Assistant Agent first，不先建设完整企业数字员工平台。
- 平台化能力不是取消，而是在项目助理 Agent 质量稳定后再分阶段产品化。
- 第一版聚焦一个项目助理 Agent，优先做好会议纪要、项目周报、风险分析、项目知识问答、审批恢复和交付物预览。
- 多领域 Agent、模板市场、完整管理后台、完整策略/模型/工具/审计/成本控制台后续建设。
- Agent 任务拆解默认自动执行，人员主要配置边界，不参与每一步拆解。
- 低风险动作自动执行，高风险动作确认或审批。
- 权限不足时可按策略动态审批，任务挂起，审批通过后断点恢复。
- 动态授权必须可配置，避免领导收到大量不必要审批。
- 权限模型采用上下文感知：用户、Agent、任务目的、数据资源、业务凭证、业务关系和风险策略共同参与判断；MVP 只做支撑项目助理闭环的最小能力。
- 多 Agent 协作、事件触发、目标驱动长期自治、记忆中心多后端等能力保留为后续平台化方向，不作为当前交付门槛。

### 2.3 已确认用户角色

当前核心用户：

- 普通员工
- 项目负责人/业务负责人
- 轻量 Agent 管理员

后续平台化用户：

- 平台超级管理员
- 企业管理员
- 审计/安全人员

### 2.4 MVP 样板场景

第一阶段推荐项目助理 Agent，验证会议纪要转行动项/任务草稿、项目周报生成、项目风险分析、项目知识问答、高风险动作动态审批、审批后断点恢复和交付物预览。专家 Agent 协作、群聊协作和多领域 Agent 创建后续建设。
