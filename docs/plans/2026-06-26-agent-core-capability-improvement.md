# Agent 核心能力提升开发规划

> 日期：2026-06-26  
> 目标：系统性提升 Agent 的回答质量、处理逻辑、工具使用、上下文优化、记忆管理、沙箱执行和安全管控能力  
> 输入：当前代码分析、产品需求文档、技术设计方案

---

## 一、现状分析

### 1.1 核心执行链路

**JavaInProcessRuntimeGateway**（1168 行）是 Agent 的核心执行引擎，主要流程：

```
startRun() 
  → AgentRunEngine.start() 
    → ContextPackageBuilder.build() 
      → executeCurrentRuntimePlan()
        → loadRuntimeMemories()
        → executeProjectAssistantIfRequested() 或通用模式
          → plan → knowledge → model_call → tool_call → artifact → self_check
```

### 1.2 关键组件现状

| 组件 | 现状 | 问题 |
|------|------|------|
| **模型网关** | ModelGateway 接口，支持 Mock 和 OpenAI 兼容适配器 | 模型调用结果没有被真正用于生成最终输出 |
| **记忆管理** | AgentMemoryService 支持 confirmed memory 读取和归档 | 只有手动确认的记忆，没有自动抽取和向量化 |
| **知识检索** | KnowledgeDocumentService.retrieve() 返回知识片段 | 检索结果作为参考资料，但没有动态权重和冲突检测 |
| **工具执行** | ToolConfigService.executeToolCall() 支持单工具和工具链 | 工具调用是预定义的（从 input JSON 读取），不是模型动态决策 |
| **上下文构建** | ContextPackageBuilder 构建输入上下文 | 没有系统 prompt、用户历史、任务上下文的分层管理 |
| **执行流程** | 线性执行 plan → knowledge → model → tool → artifact | 没有真正的 Agent 循环（observe → plan → act → reflect） |

### 1.3 核心问题诊断

#### 问题 1：回答质量低
- **现象**：项目助理的交付物（周报、风险清单、行动项）是硬编码模板
- **根因**：`buildArtifactPayload()` 方法直接返回固定格式的字符串，模型调用结果（`MODEL_RESULT` 事件）没有被使用
- **影响**：Agent 无法根据实际输入和知识生成个性化、高质量的输出

#### 问题 2：处理逻辑僵化
- **现象**：执行流程是线性的，没有循环和反思
- **根因**：`executeProjectAssistantIfRequested()` 是顺序执行，没有根据中间结果调整策略
- **影响**：无法处理复杂任务，无法从错误中恢复，无法动态调整执行计划

#### 问题 3：工具使用被动
- **现象**：工具调用由前端或上游系统预定义，不是模型自主决策
- **根因**：工具调用参数从 `inputRoot` 读取（`toolId`、`callPayloadJson`），没有让模型决定调用什么工具
- **影响**：Agent 无法根据任务需求动态选择和使用工具

#### 问题 4：上下文管理简单
- **现象**：上下文只有 inputText 和 runtimeSnapshot，没有分层
- **根因**：`ContextPackage` 只包含基础字段，没有系统 prompt、用户历史对话、任务上下文
- **影响**：模型无法获得充分的背景信息，回答缺乏连贯性

#### 问题 5：记忆管理被动
- **现象**：只有 confirmed memory 的读取，没有自动抽取
- **根因**：`loadRuntimeMemories()` 只读取已确认的记忆，没有从对话中自动抽取关键信息
- **影响**：Agent 无法从历史对话中学习，无法积累用户偏好和项目知识

#### 问题 6：安全管控不足
- **现象**：没有 Prompt 注入防护和输入校验
- **根因**：用户输入直接拼接到 prompt，没有安全边界校验
- **影响**：可能被恶意输入绕过 Agent 职责边界

## 二、提升目标

### 2.1 核心目标

让 Agent 从"模板执行器"进化为"智能助手"：

1. **回答质量**：模型真正驱动输出生成，而不是硬编码模板
2. **处理逻辑**：实现真正的 Agent 循环，支持动态调整和反思
3. **工具使用**：模型自主决策调用什么工具，而不是预定义
4. **上下文优化**：分层管理系统 prompt、用户历史、任务上下文
5. **记忆管理**：自动抽取对话中的关键信息并保存
6. **安全管控**：基础 Prompt 注入防护和输入校验

### 2.2 验收标准

- [ ] 项目助理能够根据用户输入和知识生成个性化的周报、风险清单、行动项
- [ ] Agent 能够根据中间结果调整执行计划（如知识不足时主动检索更多资料）
- [ ] 模型能够自主决定调用什么工具（如需要创建任务时调用工具）
- [ ] 上下文包含系统 prompt、用户历史对话、任务上下文
- [ ] 能够从对话中自动抽取关键信息并保存为记忆
- [ ] 基础 Prompt 注入防护（如"忽略之前的指令"类攻击）

## 三、分阶段开发计划

### P0 - 核心能力提升（让 Agent 真正可用）

**目标**：让模型真正驱动执行流程，而不是硬编码模板

#### P0-1 真实模型接入与验证
**目标**：配置并接入用户的 OpenAI 兼容模型服务，验证真实调用链路

**任务**：
1. 配置模型供应商（URL、API Key、模型参数）
2. 验证 OpenAI 兼容适配器的 chat/embedding 调用
3. 验证模型调用日志和 token 统计
4. 验证失败处理和超时控制

**交付物**：
- 模型供应商配置文档
- 真实模型调用测试用例
- 模型调用日志和 token 统计报告

**验收标准**：
- 能够通过 ModelGateway 调用真实模型
- 模型调用有日志和 token 统计
- 模型失败能返回可理解错误

**依赖**：无

---

#### P0-2 Agent 循环重构
**目标**：将硬编码的执行流程改为真正的 observe → plan → act → reflect 循环

**任务**：
1. 定义 AgentLoopExecutor 接口，封装循环逻辑
2. 实现 observe 阶段：收集上下文（用户输入、知识、记忆、历史）
3. 实现 plan 阶段：让模型生成执行计划（步骤、工具、预期输出）
4. 实现 act 阶段：执行计划中的步骤（调用工具、检索知识、调用模型）
5. 实现 reflect 阶段：让模型评估执行结果，决定是否需要调整计划
6. 实现循环控制：最大循环次数、超时控制、失败处理

**交付物**：
- AgentLoopExecutor 接口和实现
- Agent 循环测试用例
- 循环控制和失败处理逻辑

**验收标准**：
- Agent 能够根据任务生成执行计划
- Agent 能够根据中间结果调整计划
- Agent 能够在达到最大循环次数或超时后终止
- Agent 能够从错误中恢复

**依赖**：P0-1

---

#### P0-3 动态工具调用
**目标**：让模型决定调用什么工具，而不是预定义

**任务**：
1. 定义工具描述格式（toolCode、description、parameters schema）
2. 在 plan 阶段让模型选择需要调用的工具
3. 在 act 阶段执行模型选择的工具
4. 在 reflect 阶段评估工具调用结果，决定是否需要调用其他工具
5. 工具调用结果作为上下文传递给模型

**交付物**：
- 工具描述格式定义
- 模型工具选择逻辑
- 工具调用结果处理逻辑

**验收标准**：
- 模型能够根据任务需求选择工具
- 工具调用结果能够影响后续执行
- 工具调用失败能够进入失败处理路径

**依赖**：P0-2

---

#### P0-4 上下文管理优化
**目标**：分层管理系统 prompt、用户历史、任务上下文

**任务**：
1. 定义上下文分层结构：
   - System Prompt：Agent 角色、职责、边界、能力
   - User History：用户历史对话（最近 N 轮）
   - Task Context：当前任务上下文（输入、知识、记忆、工具结果）
2. 实现上下文构建器，按分层结构组装 prompt
3. 实现上下文裁剪：超过模型上下文窗口时自动裁剪历史对话
4. 实现上下文缓存：避免重复构建相同的上下文

**交付物**：
- 上下文分层结构定义
- ContextBuilder 实现
- 上下文裁剪和缓存逻辑

**验收标准**：
- 上下文包含系统 prompt、用户历史、任务上下文
- 上下文不超过模型上下文窗口
- 上下文构建性能可接受

**依赖**：P0-2

---

### P1 - 质量提升（让 Agent 好用）

**目标**：提升 Agent 的输出质量和用户体验

#### P1-1 记忆自动抽取
**目标**：从对话中自动抽取关键信息并保存

**任务**：
1. 定义记忆抽取规则（关键决策、用户偏好、项目约束）
2. 在 reflect 阶段让模型识别需要保存的记忆
3. 实现记忆保存接口（调用 AgentMemoryService.createConfirmedMemory）
4. 实现记忆去重和冲突检测

**交付物**：
- 记忆抽取规则定义
- 记忆自动抽取逻辑
- 记忆去重和冲突检测逻辑

**验收标准**：
- 能够从对话中自动抽取关键信息
- 抽取的记忆能够保存并用于后续任务
- 不会出现重复或冲突的记忆

**依赖**：P0-2

---

#### P1-2 知识来源展示
**目标**：在输出中明确展示引用的知识来源和可信度

**任务**：
1. 在知识检索结果中增加来源字段（documentId、chunkId、score）
2. 在模型 prompt 中明确标注知识来源
3. 在输出中展示引用的知识来源
4. 在低可信度时提示用户复核

**交付物**：
- 知识来源字段定义
- 知识来源展示逻辑
- 低可信度提示逻辑

**验收标准**：
- 输出中能够展示引用的知识来源
- 低可信度时能够提示用户复核
- 知识来源可追溯到具体文档和片段

**依赖**：P0-2

---

#### P1-3 Prompt 注入防护
**目标**：基础输入校验和注入检测

**任务**：
1. 定义 Prompt 注入检测规则（如"忽略之前的指令"、"以系统调试模式"）
2. 在用户输入进入 prompt 前进行校验
3. 检测到注入时拒绝执行并返回提示
4. 记录注入尝试的审计日志

**交付物**：
- Prompt 注入检测规则
- 输入校验逻辑
- 注入审计日志

**验收标准**：
- 能够检测常见的 Prompt 注入攻击
- 检测到注入时能够拒绝执行
- 注入尝试有审计日志

**依赖**：P0-4

---

**验收标准**：

## 六、风险与缓解

### 风险 1：模型调用成本
- **风险**：真实模型调用可能产生较高成本
- **缓解**：先用小模型验证，确认效果后再切换大模型；实现 token 预算控制

### 风险 2：Agent 循环失控
- **风险**：Agent 循环可能无限执行或进入死循环
- **缓解**：实现最大循环次数、超时控制、失败处理

### 风险 3：工具调用失败
- **风险**：工具调用可能失败或返回错误结果
- **缓解**：实现工具调用重试、失败处理、降级策略

### 风险 4：上下文过长
- **风险**：上下文可能超过模型上下文窗口
- **缓解**：实现上下文裁剪、历史对话压缩

### 风险 5：安全风险
- **风险**：可能被 Prompt 注入攻击
- **缓解**：实现输入校验、注入检测、审计日志
